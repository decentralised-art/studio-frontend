# Music Theory Corpus Plan

This document plans the long-term corpus of musical concepts to encode as reusable connector-network nodes.

It does not define a deployment batch. It defines what the corpus should try to cover.

The more systematic exploratory workspace now lives in:


## Goal

Build a broad, reusable musical concept network:

```text
music-theory concept
  -> exact connector-tree node where possible
  -> documented RI controls
  -> documented conceptual relations
  -> reusable dependency for higher-level composition connectors
```

The goal is not tonal harmony specifically. The goal is a wide mathematical and historical corpus of musical materials: pitch sets, interval cycles, named sonorities, modes, rhythmic systems, serial operations, dynamic contours, textures, and compositional procedures.

## Corpus Principles

1. Encode grammars and reusable materials before named presets.
2. Include famous named objects as metadata or wrappers when they are specific instances of broader grammars.
3. Include historically important named sonorities even when they are not generated by a simple scale grammar.
4. Prefer connector reuse when the runtime tree actually uses the child connector.
5. Use conceptual ancestry metadata when the historical/theoretical relation is real but not a runtime dependency.
6. Keep world-agnostic names where possible.
7. Do not limit the corpus to common-practice tonal theory.
8. Do not deploy speculative trees until exact dependencies, RI positions, and smoke outputs are documented.

## Layer 1: Pitch-Class And Interval Operations

This is the foundation for a large part of the corpus.

### Operations To Represent

```text
transposition
inversion
retrograde for ordered rows
rotation of cyclic grammars
complement
union
intersection
set-class normalization
interval vector
ordered interval cycle
unordered pitch-class set
pitch-class multiplication modulo 12
axis reflection
registral displacement
```

Some of these can be connector trees now. Others may start as metadata or require new transformations.

### Exhaustive 12-TET Set-Class Corpus

We should include the full 12-TET pitch-class set-class universe as a reference corpus.

Each set-class node should eventually document:

```text
prime form
Forte number where applicable
interval vector
cardinality
complement
inversion relation
symmetry
named musical uses where known
deploy status
```

This is broader and more neutral than a list of familiar scales. It gives us a rigorous post-tonal backbone for chords, scales, and collections.

Potential connector strategy:

```text
pitch_class_set_4_27_v1
pitch_class_set_6_35_v1
pitch_class_set_8_28_v1
```

But the final naming scheme should be chosen carefully before deployment.

## Layer 2: Ordered Interval Cycles

These are cyclic pitch grammars where the transformations are ordered intervals.

Already deployed examples:

```text
chromatic_steps_v2                 [1]
diatonic_heptatonic_steps_v2       [2,2,1,2,2,2,1]
anhemitonic_pentatonic_steps_v2    [2,2,3,2,3]
whole_tone_steps_v2                [2]
octatonic_steps_v2                 [1,2]
```

Future corpus should include:

```text
all period-12 ordered interval partitions up to selected complexity
all symmetric period-12 cycles
all low-cardinality cycles with high musical relevance
microtonal / n-EDO versions later, if MusicXML support is extended
```

Named rotations should be RI shift metadata before they are separate connectors.

## Layer 3: Modes Of Limited Transposition

Messiaen's modes of limited transposition should be explicitly included.

These belong naturally in the concept network because they are mathematical pitch collections with constrained transpositional behavior.

Candidate interval grammars:

```text
Mode 1: [2,2,2,2,2,2]
Mode 2: [1,2,1,2,1,2,1,2]
Mode 3: [2,1,1,2,1,1,2,1,1]
Mode 4: [1,1,3,1,1,1,3,1]
Mode 5: [1,4,1,1,4,1]
Mode 6: [2,2,1,1,2,2,1,1]
Mode 7: [1,1,1,2,1,1,1,1,2,1]
```

These should be documented with:

```text
number of distinct transpositions
set class / prime form where known
complement
contained triads or characteristic subsets
Messiaen mode number
rotation behavior
```

Important: Mode 1 and Mode 2 already correspond to deployed `whole_tone_steps_v2` and `octatonic_steps_v2` grammars. The Messiaen-specific concept docs should point to those deployed nodes rather than redeploying duplicate materials.

## Layer 4: Named Sonorities And Special Chords

The corpus should include named sonorities, not because they are all foundational, but because they are important reusable cultural/theoretical nodes.

Include at least:

```text
Tristan chord
Prometheus / Mystic chord
Petrushka chord
Elektra chord
all-interval tetrachords
Viennese trichord
French sixth / German sixth / Italian sixth as named sonorities
quartal and quintal stacks
added-sixth and added-second sonorities
suspended sonorities
tone clusters
hexatonic poles / augmented-triad cycles
```

Documentation policy:

```text
original spelling where historically relevant
pitch-class set-class representation
possible connector tree
whether it is better represented as a pitch-class set, ordered voicing, or product table
known source/context
```

Examples:

```text
Tristan chord
  treat as named sonority, original spelling matters
  also document set-class relation, commonly discussed as Forte 4-27 / half-diminished seventh related

Prometheus / Mystic chord
  treat as named six-note synthetic sonority/collection associated with Scriabin
  common C form: C, F#, Bb, E, A, D
```

Named sonorities should not automatically become note tables. First document them as pitch-class or voicing concepts; then decide whether a MusicXML-compatible table is useful.

## Layer 5: Scale And Mode Families Beyond Tonal Harmony

The corpus should cover scale systems broadly, without making tonal function the organizing principle.

Include:

```text
church/diatonic mode family as rotations of diatonic grammar
harmonic minor family
melodic minor family
double harmonic / Byzantine family
Hungarian minor family
acoustic / Lydian dominant family
altered / super-Locrian family
bebop scale families
blues scale variants
hexatonic systems
augmented scale
diminished scale / octatonic system
whole-tone system
synthetic scales from modernist theory
maqam/raga-inspired pitch collections only with clear caveats
```

Caveat for non-Western systems:

```text
pitch_midi and 12-TET cannot fully represent intonation, ornament, hierarchy, melodic grammar, or performance practice.
```

So these should initially be documented as approximate pitch-material nodes only, unless the world/plugin later supports richer scalar semantics.

## Layer 6: Serial And Post-Tonal Operations

Include operations from serial and post-tonal theory:

```text
twelve-tone row
prime row
inversion
retrograde
retrograde inversion
row matrix
hexachordal combinatoriality
derived rows
partitioning
aggregate completion
all-combinatorial hexachords
set multiplication
K-net / transformational relations later if useful
```

Connector strategy:

```text
row as ordered pitch-class cycle
row form as RI/transformation metadata where possible
matrix as higher-level concept, not necessarily one connector
```

Some serial operations may require transformations not currently deployed. Start with rows and ordered pitch-class cycles.

## Layer 7: Rhythm And Time

The corpus should treat rhythm as mathematical material, not just note values.

Include:

```text
fixed grids
ordered time partitions
additive rhythms
Euclidean rhythms
non-retrogradable rhythms
augmentation
diminution
isorhythm: talea and color
rhythmic modes
phase / rotation systems
tuplets and proportional divisions
aksak-like asymmetrical cycles
tala-inspired cycles with caveats
ostinato and repeating cells
rests / note_kind masks
```

Messiaen's non-retrogradable rhythms should be included as rhythm concept nodes.

Implementation note:

```text
some rhythm concepts can be onset_tick streams
some are duration_tick streams
some require note_kind/rest masks
some require product tables
```

## Layer 8: Dynamics, Articulation, And Notational Qualities

Include:

```text
velocity constants
velocity contours
crescendo / diminuendo
accent cycles
dynamic_code cycles
staccato / tenuto / accent / marcato articulations
slur pair structures
beam group structures
ornament codes later
```

These should be optional product-table dimensions. A note table can be MusicXML-compatible without them, but richer compositions should reuse them.

## Layer 9: Texture, Counterpoint, And Voice Relations

Avoid tonal-harmony-specific assumptions, but include general voice/texture operations:

```text
parallel interval stream
contrary motion
inversional symmetry around axis
pedal point / drone
ostinato
canon by temporal offset
canon by pitch transformation
hocket
heterophonic doubling
register split
voice crossing constraints
density layers
```

Many of these are C4 or C5 concepts. They need exact RI projection and smoke tests before deployment.

## Layer 10: Form And Large-Scale Procedures

Include:

```text
sequence
rotation form
palindrome
arch form
process music transformations
phase shifting
additive process
subtractive process
call-response
variation chain
```

Most of these will be composition-level connector trees rather than low-level musical materials.

## Documentation Strategy

Every concept should first be documented in one of three forms:

```text
concept-only
  historically/theoretically important but not yet expressible as a tree

tree-candidate
  exact connector tree can be written but not deployed

deployed-curated
  onchain and recommended for reuse
```

Each node must specify whether it is:

```text
pitch material
rhythm material
duration material
dynamic material
sonority
note table
voice table
composition root
metadata table
```

## Immediate Planning Work Before Any New Deployment

No new deployment should happen until we have:

1. A pitch-class set-class documentation strategy.
2. A named-sonority documentation strategy.
3. A Messiaen modes concept page.
4. A rhythm concept page for non-retrogradable and additive rhythms.
5. A decision about whether named sonorities should deploy as pitch-class materials, ordered voicings, or note-table examples.
